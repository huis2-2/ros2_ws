하드웨어/제어 코드 변경 기록
============================

2026-09-30
- 처음 전달된 배선 기록
  * Jetson 물리 3번(SDA) -> PCA9685 SDA
  * Jetson 물리 5번(SCL) -> PCA9685 SCL
  * Jetson 물리 39번(GND) -> PCA9685 GND
  * PCA9685 CH8 -> MUX S1 (조향 자동 입력)
  * PCA9685 CH9 -> MUX S2 (속도/ESC 자동 입력)
  * RC 수신기 ST -> MUX M1 (조향 수동 입력)
  * RC 수신기 TH -> MUX M2 (속도 수동 입력)
  * RC 수신기 AUX -> Jetson 물리 15번(GPIO 입력)
- pca9685_drive_test.py 추가
  * PCA9685 CH8 조향 및 CH9 속도 명령을 키보드로 단계 조절
  * 각 채널 번호, 펄스폭(us), 조향 방향, 속도 명령 비율 표시
  * Jetson 물리 15번 핀에서 AUX 펄스폭과 LOW/MID/HIGH 상태 표시
  * 시작 및 종료 시 ESC 중립(1500 us), 조향 중앙(1600 us) 적용
  * 실제 출력 없이 확인할 수 있는 --dry-run 옵션 추가
  * I2C 버스/주소/주파수와 PWM 보정값 입력 검증 추가
- 안전 확인 사항
  * PCA9685 VCC는 로직 전원이다. Jetson I2C와 함께 쓸 때는 Jetson 3.3V
    (물리 1번 또는 17번)에 연결하고, 서보/ESC용 5~6V는 PCA 보드의 V+에
    별도 공급한다. VCC에 Jetson 물리 2번(5V)을 직접 연결하지 않는다.
  * RC 수신기 AUX 출력이 5V이면 Jetson 물리 15번에 직접 넣지 말고
    3.3V 레벨 시프터 또는 저항 분압기를 사용한다.
  * 모든 장치의 GND는 공통으로 연결한다.

앞으로 배선, 핀 번호, PWM 보정값 또는 제어 코드가 바뀌면 날짜와 함께
이 파일에 계속 기록한다.

2026-09-30 (배선 정정)
- RC 수신기 AUX -> Jetson 물리 15번 연결을 제거했다.
- MUX SEL -> Jetson 물리 15번 연결로 변경했다.
- pca9685_drive_test.py에서 15번 핀의 AUX 입력 측정 기능을 제거했다.
- Jetson 물리 15번에서 MUX 선택용 50 Hz, 10% duty(약 2000 us) PWM을
  출력하도록 변경했다.
- 안전한 전환을 위해 PCA9685 CH8을 중앙, CH9를 중립으로 먼저 설정한 뒤
  MUX SEL 출력을 시작하도록 초기화 순서를 변경했다.
- --mux-pin, --mux-frequency, --mux-duty, --no-mux 옵션을 추가했다.
- 오류 발생 단계(I2C, CH8/CH9, MUX SEL)를 터미널에 표시하도록 개선했다.

2026-09-30 (I2C 버스 확인)
- Jetson 모델을 NVIDIA Jetson Orin Nano Engineering Reference Developer Kit
  Super로 확인했다.
- I2C bus 1의 주소 0x40은 내장 전력 모니터 ina3221이 사용 중이어서
  기존 --i2c-bus 1 실행 시 Errno 16(Device or resource busy)이 발생했다.
- 물리 3번(SDA), 5번(SCL)이 연결된 I2C bus 7의 주소 0x40에서 PCA9685
  MODE1 레지스터 값 0x11이 정상 응답하는 것을 확인했다.
- pca9685_drive_test.py의 기본 I2C 버스를 1에서 7로 변경했다.
- --no-mux 사용 시 상태 화면에 MUX SEL이 OFF라고 표시하도록 수정했다.
- Jetson.GPIO PWM 정지 후 핀이 먼저 해제되는 환경에서 발생하던 종료 예외를
  수정했다. MUX SEL duty를 0%로 내린 뒤 PWM 정지 및 GPIO 정리를 수행한다.

2026-09-30 (PCA9685 출력 정지 원인 수정)
- 화면의 CH8/CH9 값은 바뀌지만 조향이 움직이지 않는 현상을 점검했다.
- PCA9685 MODE1 레지스터가 0x31로 확인되어 SLEEP 비트가 켜져 있었고,
  내부 발진기가 정지해 실제 PWM 파형이 출력되지 않는 상태였다.
- 초기 MODE1 상태와 관계없이 SLEEP 비트를 명시적으로 해제한 뒤 RESTART와
  auto-increment를 설정하도록 주파수 초기화 코드를 수정했다.

2026-09-30 (MUX SEL 구동 방식 보완)
- 1000 us와 2000 us 선택 펄스에서 화면 값은 바뀌지만 물리 조향이 전달되지
  않는 현상을 확인했다.
- MUX SEL이 일반적인 디지털 선택 입력일 가능성을 반영해 high, low, pwm
  세 가지 구동 방식을 지원하도록 변경했다.
- 기본 MUX SEL은 디지털 HIGH로 설정했다. 반대 입력 선택은
  --mux-mode low, RC 펄스형 선택기는 --mux-mode pwm으로 시험할 수 있다.

2026-09-30 (MUX SEL 방식 확정)
- 사용자 확인에 따라 MUX SEL은 RC 방식 PWM 펄스폭으로 RC 수신기 입력과
  Jetson/PCA9685 입력 중 하나를 선택하는 핀으로 확정했다.
- --mux-mode 기본값을 high에서 pwm으로 변경했다.
- 기본 50 Hz, 10% duty(약 2000 us)는 Jetson/PCA9685 입력을 선택하고,
  50 Hz, 5% duty(약 1000 us)는 RC 수신기 입력을 선택하는 것으로 표시한다.

2026-09-30 (조향 중앙 및 방향 1차 보정)
- 기존 시작값 1600 us에서 바퀴가 오른쪽으로 꺾이고, 더 큰 값에서 서보
  버징이 발생하는 것을 확인했다. 기계적 끝점에서의 스톨 가능성이 있어
  해당 설정 사용을 중단했다.
- 조향 중앙 기본값을 1600 us에서 표준 중립값 1500 us로 변경했다.
- 초기 시험 범위를 왼쪽 1400 us, 오른쪽 1600 us로 좁혔다.
- 실제 관찰 방향에 맞춰 a는 1400 us 쪽, d는 1600 us 쪽으로 이동하도록
  조향 방향을 반전했다.

2026-09-30 (키보드 조향 입력 개선)
- 기존 input() 방식은 a/c/d 입력 뒤 Enter가 필요했고, a/d 한 번당 25 us만
  바뀌어 실제 조향 변화가 눈에 잘 띄지 않았다.
- 터미널에서는 Enter 없이 한 키를 즉시 읽도록 변경했다.
- a는 왼쪽 끝값, c는 중앙값, d는 오른쪽 끝값을 바로 출력하도록 변경했다.
- j/l은 설정된 step(기본 25 us)만큼 좌/우로 미세 조정하도록 추가했다.
- 파이프 입력과 --dry-run 시험에서는 기존 줄 단위 입력을 계속 지원한다.

2026-09-30 (LiDAR 장애물 정지)
- 연결된 LiDAR를 USB ID 10c4:ea60(Silicon Labs CP2102N), /dev/ttyUSB0에서
  확인했다. 고정 by-id 경로의 장치 시리얼은 12f6e4544f6eef1189d8e7c2c169b110이다.
- 기존 실행 기록과 실제 통신 결과로 Slamtec C1, 460800 baud, Standard 모드,
  /scan 토픽, 약 10 Hz, 최대 거리 16 m임을 확인했다.
- lidar_stop_drive.py를 추가했다. test3.py의 CH8 및 초기 속도 1565 us를
  유지하며, 전체 360도 스캔에서 0.30 m 이하 장애물 감지 시 1500 us로
  정지한다. 첫 스캔 전과 스캔 단절 시에도 중립을 유지한다.
- 장애물 또는 센서 단절로 정지하면 자동 재출발하지 않도록 래치 방식으로
  구현했다.
- run_lidar_stop_rviz.sh를 추가해 Slamtec C1 노드, /scan RViz 화면,
  lidar_stop_drive.py를 한 명령으로 실행하고 함께 종료할 수 있게 했다.

2026-09-30 (정면 장애물 및 10초 주행 제한)
- 장애물 검사 범위를 전체 360도에서 LiDAR 정면 0도를 중심으로 좌우 30도
  구간으로 변경했다. 뒤와 옆의 가까운 물체는 정지 조건에서 제외한다.
- 정면 장애물이 0.30 m 이내면 즉시 정지하며, 장애물이 없더라도 주행 시작
  10초 후 자동으로 정지하도록 제한했다.
